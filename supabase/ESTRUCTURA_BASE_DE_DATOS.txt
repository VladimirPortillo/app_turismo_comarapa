1) auth.users  (tabla propia de Supabase Auth, no se crea aquí)
   - id (uuid) PK

2) public.usuarios
   - id            uuid PK  --> FK a auth.users(id)  [on delete cascade]
   - nombre        text
   - correo        text
   - rol           rol_usuario  (default 'editor')
   - activo        boolean
   - created_at / updated_at
   Relación: 1 a 1 con auth.users (perfil del panel de administración)

3) public.categorias   (tabla maestra de tipos, editable por el admin)
   - id            uuid PK
   - entidad       entidad_categoria  (a qué módulo pertenece)
   - nombre        text
   - icono         text
   - orden         smallint
   - activo        boolean
   UNIQUE (entidad, nombre)
   Relación: es referenciada por categoria_id desde lugares, hoteles,
             restaurantes, actividades, gastronomia y eventos.
             Un trigger valida que la categoría elegida pertenezca
             al mismo módulo (ej. un "lugar" no puede usar una
             categoría de "hotel").

4) public.lugares
   - id                    uuid PK
   - categoria_id          uuid  --> FK a categorias(id)  [on delete set null]

   - mejor_epoca, activo
   Relación: referenciado por resenas (relación lógica, sin FK).

5) public.hoteles

   - latitud, longitud, direccion_referencia
   - precio_min, precio_max, servicios[]
   - contacto_reservas, calificacion_promedio, activo
   Relación: referenciado por resenas (relación lógica, sin FK).

6) public.restaurantes
   - id                    uuid PK
   - categoria_id          uuid  --> FK a categorias(id)  [on delete set null]
   - nombre, descripcion, imagenes[]
   - latitud, longitud, direccion_referencia
   - horario_atencion, precio_referencial, contacto
   - calificacion_promedio, activo
   Relación: referenciado por gastronomia.restaurante_id y por
             resenas (relación lógica, sin FK).

7) public.actividades
   - id                    uuid PK
   - categoria_id          uuid  --> FK a categorias(id)  [on delete set null]
   - nombre, descripcion, imagenes[]
   - latitud, longitud
   - dificultad            nivel_dificultad
   - duracion_min, precio_referencial
   - operador_contacto, capacidad_maxima, temporada, activo
   Relación: referenciado por resenas (relación lógica, sin FK).

8) public.gastronomia
   - id                    uuid PK
   - categoria_id          uuid  --> FK a categorias(id)        [on delete set null]
   - restaurante_id        uuid  --> FK a restaurantes(id)      [on delete set null]
   - nombre, descripcion, imagenes[]
   - temporada, precio_referencial, activo
   Relación: puede indicar "dónde encontrarlo" apuntando a un
             restaurante (opcional).

9) public.eventos
   - id                    uuid PK
   - categoria_id          uuid  --> FK a categorias(id)  [on delete set null]
   - nombre, descripcion, imagenes[]
   - latitud, longitud
   - fecha_inicio, fecha_fin, periodicidad, activo

10) public.resenas
   - id                    uuid PK
   - entidad               entidad_resenable  ('lugar'|'hotel'|'restaurante'|'actividad'|'evento'|'gastronomia')
   - entidad_id            uuid   (SIN FK: relación polimórfica)
   - autor_nombre, calificacion (1-5), comentario
   - estado_moderacion     estado_moderacion  (auto-aprobada desde script 06)
   - created_at
   Relación: "entidad" + "entidad_id" apuntan a una fila de lugares,
             hoteles, restaurantes, actividades, eventos o
             gastronomia, según el valor de "entidad". La integridad
             se valida en la aplicación, no con una FK de base de
             datos (porque puede apuntar a distintas tablas).
